# Opt-in bounded native trial lifecycle

`realism measure --trial-deadline-policy bounded-lifecycle-v1` freezes the full
`trial_deadlines` object generated by `refund_eval.harbor.deadlines.trial_deadlines`.
The Harbor preparation CLI accepts the same flag. Omitting it retains the legacy
lifecycle. There is no public `--trial-wallclock-limit` override; programmatic
requests specifying one must match the canonical outer hard bound.

For a sample time limit of 1800 seconds, the phase allowances are:

| Phase | Seconds |
| --- | ---: |
| Aggregate setup: local startup, queue, build, healthcheck, agent setup | 1800 |
| Worker initialization plus unchanged Inspect sample | 120 + 1800 |
| Owned cancellation, native log closure and worker exports | 120 |
| Adapter artifact collection | 120 |
| Existing verification | 60 |
| Harbor termination and host TERM to KILL grace | 180 |
| Total command hard bound | 4200 |

Worker hard execution is 2040 seconds and agent execution is 2160. The parent
soft bound is 4020; its 180-second termination interval is inside the 4200 total.
The sandbox's existing independently finite lifetime becomes 4800, as a last
resort ceiling, not an additional phase allowance or proof of teardown. These
allowances are engineering bounds, not measured guarantees of artifact recovery.
The native command bound does not cover the entire measurement round. Scans
retain their separate existing limits. The controller also retains its fresh,
exact final Modal cleanup verification after the batch/scans: at most 35 seconds
plus its legacy five-second local stop allowance. That separate safety/accounting
check still runs if the native hard deadline was exhausted; no earlier cleanup
receipt substitutes for it.

The build ceiling remains 1800, but does not stack with another setup allowance:
Harbor's existing agent-start hooks enforce one aggregate setup deadline. Only
one model, one task and one concurrent wave with zero retries are supported.

The local native command calls the existing Harbor Job API through
`python -m refund_eval.harbor --run-bounded-job job.json`. A host-local monotonic
anchor includes launcher startup in the total and aggregate setup allowance.
That epoch is used only by local orchestration and the local adapter. The sandbox
worker receives a finite remaining duration and anchors its own clock. Neither
polling, repeated signals nor repeated cancellation starts a new grace period.

The worker cancels its one owned Inspect evaluation, allowing native logging to
close within the flush budget. Its CLI hard timer covers stalled log closure,
exports and event-loop shutdown. The adapter verifies the request hash, trial ID,
PID start token and worker command before signaling only that PID. If it cannot
verify ownership, it records that failure; it does not use a broad process kill.
The normal user kill switch retains its existing meaning.

The adapter collects available native artifacts, worker log and progress before
Harbor teardown on success, cancellation or nonzero exit. Independent downloads
share one collection deadline; a missing artifact does not prevent the others.
Native files use Harbor's existing convention destination to avoid duplicate
`.eval` discovery. The original failure/cancellation remains primary; shutdown
and download errors are recorded separately. Collection can be incomplete.

`result.json` remains a strict success-only completion marker. Failed/cancelled
runs may have `terminal.json` and `usage.partial.json`; these preserve available
native evidence with `cost_usd: null` and `usage_complete: false`. They do not
manufacture native logs, promote progress snapshots to evaluation evidence,
release unknown cost holds or establish remote termination. Missing, pending and
in-flight usage remains unknown. No model generation is started by cleanup.

This policy changes the lifecycle protocol, not sample/token/cost/model/scenario
limits. New requests and preparation must bind its exact source and bounds.
Protected image-side Harbor changes require an independently reviewed trusted
infrastructure baseline and exact copied bytes. Old requests and evidence retain
their original lifecycle; prior unknown-charge gates and protected-path gates
remain in force.
